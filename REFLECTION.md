The biggest shift in this assignment was moving from class components to function components with Hooks. In lecture, state lived in this.state and changed through this.setState. Here, useState gave each component its own state value and setter, and the code became shorter and easier to follow because there is no this and no handler binding. The project filter showed me an idea I had not appreciated before: the filtered list should not be stored in state at all. The query is the only state; the visible projects are calculated from it on every render. My first instinct was to keep a second array in state and update it with an Effect, which would have created two sources of truth that could drift apart.

Routing was the part I understood least at the start. Building the layout route with Outlet made it clear how one header and footer can wrap every view, and NavLink's end prop explained why the Home link was highlighted on every page until I added it. Handling the two missing-page cases also made me think more carefully: an unknown URL is caught by the wildcard route, but an unknown project slug matches a real route and only fails when the data lookup returns nothing, so the detail component has to handle it itself.

Deployment taught me the difference between asset paths and route paths. Vite's base setting makes the built HTML request /portfolio/assets/ rather than the domain root, while HashRouter keeps routes after the # so refreshing a project page never asks GitHub Pages for a file that does not exist. Running lint and the production build locally, and then testing a preview, caught problems before they reached the live site.

For my extension I chose the persistent theme. It was a good example of what an Effect is actually for: synchronising React state with something outside React, in this case the html element and localStorage. I also learned to wrap storage access in try/catch, because it can fail in private windows.
